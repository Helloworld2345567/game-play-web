# 性能与弱网优化

更新时间：2026-09-07

架构与协议契约以 [`CONTEXT.md`](../CONTEXT.md) 为准。优化以实测 p95/p99 和正确性回归为依据。

## 第一批：动作交付与恢复（P1）

1. **严格动作确认**：HTTP 成功响应可确认本次命令；未知结果强制完整同步，未提交则提示重试。WebSocket 确认等待和初始快照等待均有 8 秒截止时间；204 心跳不充当动作回执，不自动重放严格命令。
2. **普通 JSON 请求预算**：排行榜、进度和统计的单次请求默认最多 8 秒，含响应体读取；最多尝试 2 次、总预算 15 秒。页面取消不重试，推箱子 HTTP 错误继续由 outbox 调度。建房仅尝试一次，30 秒内返回或解除等待，避免自动重试创建重复房间；首次会话保留原有身份建立策略。
3. **HTTP 自动恢复 WebSocket**：首次后台探测约 10 秒，失败退避至约 60 秒并加抖动，隐藏页不探测。探测期间 HTTP 继续工作；收到追平快照且 HTTP 请求及 pending 全部结束后才切换，保持原 connectionId 和动作序号。名额不足时保留 HTTP。
4. **本地耗时指标**：浏览器发出 `room-session-metric` CustomEvent，包含 `name`、`durationMs`、`transport` 和可选 `outcome`。`action_delivery` 表示提交到处理结果的耗时；`connection_recovery` 表示恢复到可用状态；`websocket_recovery` 表示本次降级到恢复 WS 的耗时。严格动作的 `state_advanced` 只表示 revision 已推进，不能当作精确动作回执。事件无身份、房间 ID 或 payload，不主动上传。

验收条件：弱网、响应丢失、WebSocket 禁用和恢复场景下没有永久 pending、重复生效或序号倒置；`204`、完整同步和多标签页动作都能维持同一语义。

主要回归：`npm test`、`npm run test:worker`，以及 `npm run test:e2e -- tests/e2e/websocket-fallback.spec.ts --workers=1`。浏览器回归覆盖提交前失败、提交后响应丢失、自动升级、无快照探测、切换期间并发动作顺序及升级后立即退出。

## 第二批：会话、游戏接入与重复工作（P2）

- **RoomSession**：页面 Hook 只做订阅与操作转发；显式连接状态取代分散的生命周期标记，统一清理退出/终止路径。独立测试覆盖乱序回包、确认超时、自动升级、退出确认和定时器释放；未变化的 HTTP 心跳不触发页面更新。
- **生命周期边界**：HTTP 截止时间覆盖等待共享身份初始化和响应体读取；服务端为显式退出的连接保留短期关闭记录，阻止迟到请求重新建立租约。拒绝回执响应丢失时，通过同一动作身份重发取回幂等回执，不修改业务 revision。
- **游戏接入**：启动选择器、展示文案、席位和错误适配收拢到各游戏目录；静态 catalog 组合能力，首页与房间页通用消费，renderer 继续懒加载并校验 game/rule 配对。
- **棋盘绘制**：五子棋、象棋缓存稳定棋盘位图，预览变化只合成缓存和交互提示。叠叠高暂停后停止动画循环，恢复、尺寸变化等事件触发必要绘制；终局保留碎块和镜头收尾动画，结束后停止。浏览器用例直接计数 Canvas/WebGL 调用，验证缓存复用、暂停停止及恢复。
- **目录和房间存储**：目录按 Guest、房间租约和 bootstrap 拆分记录，统计使用事务内维护的计数。正常心跳只写当前 Guest，续期保留安全的较早 alarm；到期才扫描清理。房间合并租约清理与续期写入，相同 alarm 不重复调度。

可复现测量：`npm run test:worker -- tests/room-directory-performance.integration.test.ts`。固定时间、100 Guest（各 1 个 Presence）、10 个已激活房间；不含初始化和到期清理，心跳按最早到期顺序续期。

| 工作量 | 旧整表模型估算 | 当前实测 |
| --- | --- | --- |
| 100 次统计 | 200 次 put、100 次 setAlarm、1,203,200 B | 0 次写入/调度 |
| 100 次心跳 | 200 次 put、100 次 setAlarm、1,203,200 B | 100 次 put、0 次 setAlarm、9,600 B |

当前两项均无目录 list；字节数只计 JSON value 的 UTF-8 大小，不代表网络传输或 Cloudflare 计费量。收益是重复工作减少，线上 p95/p99 尚未压测。

目录首次访问会在事务内迁移旧整表并删除旧键。迁移后回滚必须保留新版目录读取代码，或先反向迁移；直接部署旧版目录代码会误读容量与在线状态。

## 后续：按测量推进

- 采集输入到可见反馈、动作到确切回执、对手可见延迟，并分别比较 WebSocket/HTTPS、暖连接/冷恢复和不同 RTT。
- 采集房间排队、规则计算、持久化、投影和广播序列化的 p95/p99；只有确认重复工作后再合并存储或优化快照。
- 采集本地游戏帧时间、长任务、缓存重建和空闲绘制，并在参考手机上核实缓存的内存成本与实际收益。
- 仅在快照字节数和发送量证明需要时评估序列化缓存或 delta；缺口必须自动回到完整快照。
- 用参考手机和 30/150/300 ms RTT、抖动、响应丢失、长局、10 房间压力做可重复基线，再决定地域或协议调整。

每项优化都应保留规则确定性、观看者隔离和服务端权威裁决，并附带可复现的性能对比与回归结果。
